# 历史记忆

这份记忆来自 vNext 这几轮讨论和实现，用来防止下一轮又把项目做回“论文库后台”。

## 最初的判断

用户的核心工作不是在这里精读论文。这个系统更像大脑思维的脚手架：把论文、关系、路径、问题、假设、结论、任务和外部 AI 往返组织起来。

旧系统有内容积累，但界面像后台，功能页面割裂。vNext 的方向是 Codex-like 个人研究 OS：线程是容器，Atlas 是高频上下文选择场，Context Canvas 是思维编排板，右栏是对象/模板/上下文 inspector，Codex 和外部 API 是外脑。

## 稳定产品语义

- 项目：成果目标，例如综述、章节、实验报告。
- 线程 / 研究问题：围绕项目推进的具体问题，不是“看一篇论文”。
- Atlas：论文关系图谱与路线 × 年份扫视场，不是 PDF 阅读器。
- Context Canvas：组织问题、假设、结论、材料和下一步任务的结构化思维板。
- 对象记忆：跨线程复用的个人判断层，保存论文、关系、候选、路径的长期判断。
- Task Pack：复制给 Codex 或由 API 发送的上下文包。
- 回挂：Codex/API 返回经用户确认后，写入结果卡、Canvas 节点、对象记忆或实验运行。

## UI 方向

目标是 Codex Mac 风格：

- 清爽、圆润、低边界。
- 不要纸张质感、尖锐表格、重阴影、渐变块和后台表单感。
- 彩色只用于极简线条、状态点、路线细描边和节点类型区分。
- 左栏负责项目、线程、Atlas 选择；不要堆功能导航。
- 中央是当前工作面：聊天、Atlas、Context Canvas、论文阅读页或实验运行页。
- 右栏默认打开，但像 inspector，不像后台配置面板。
- 普通输入是消息；只有 `/` 前缀才执行命令。

## 已经做过的方向迭代

1. 从旧 `desktop.html` 外壳迁移到 `vnext/frontend` + `vnext/service`。
2. 个人数据真相改为 `data/personal` 文件层，不进入旧 SQLite。
3. Atlas 视觉从旧表格/纸卡改为更轻的路线 × 年份对象层。
4. 右栏从常驻重面板改成对象优先 inspector。
5. 加入项目、线程、对象记忆、Task Pack、结果卡、工具运行记录。
6. Context Canvas 增加问题、假设、结论、材料、任务和语义边。
7. 加入研究动作模板：空白分析、方法演化、关系/路径解释、候选审查。
8. 加入真实消息流，普通输入写入线程消息。
9. 论文详情从右侧滑出为阅读页，占中间 + 右栏，不遮左栏。
10. 论文页支持对象记忆、结构化阅读字段和页内对话。
11. 论文更新吸收旧版候选审查思路：候选论文以虚框卡落到 Atlas 中。
12. 研究实验室吸收旧 AI Scientist / BFTS 思路：Canvas 任务/假设生成实验运行。

## 不能再反复踩的偏差

- 不能把首页做成仪表盘。首页应是 Codex-like 起点，输入框是主锚点。
- 不能把 Atlas 做成阅读器。Atlas 的价值是扫视关系和组上下文。
- 不能把 Canvas 做成普通白板。Canvas 是论证结构，不追求无限画布炫技。
- 不能把 Tools 做成旧后台入口合集。Tools 应以运行回看和高频动作优先。
- 不能把 API 调用做成默认 agent。复制给 Codex仍是主路径，API 是用户确认后的辅助。
- 不能自动写回旧 bundle 或 SQLite。所有新增个人层先进入 `data/personal`。

# EAI Desktop 1.0 产品介绍

## 产品定位

EAI Desktop 是面向个人研究者的本地优先科研工作台。它解决的不是“再做一个聊天窗口”，而是让研究问题、来源、阅读记录、判断、实验和写作形成一条可追踪的工作链。

系统提供四类明确结果：

1. **询问（AskTurn）**：处理日常问题和快速信息查询。
2. **研究任务（ResearchTask）**：后台持续检索、阅读、比较和核验，形成证据化报告。
3. **研究 Campaign**：在证据和假设成熟后，进入实验、写作、审稿与发布闭环。
4. **系统操作**：通过注册能力读取或修改 EAI 内部对象，所有持久修改均可预览、确认和审计。

这四类结果不会混在一起。研究任务不会占用普通 Composer；向研究任务追加要求必须定向发送；普通询问不会被误当作任务 steer；实验 Campaign 需要用户显式升级。

## 询问与研究任务

### 询问

信息型询问会执行一次有界并行检索，并在截止时间后使用已经获得的结果完成回答。允许的来源包括：

- 当前线程目标和最近消息
- 当前论文或焦点对象
- Atlas 与线程固定资料
- 本地文档和对象记忆
- OpenAlex、arXiv、Crossref 等学术连接器
- 已配置的 SearXNG、Brave 或 Tavily 网页连接器

闲聊、改写、翻译、摘要格式转换和创作不会为了“显得自主”而搜索。每轮执行摘要会告诉用户实际读取和搜索的范围，以及本轮是否可能修改工作区。

### 研究任务

研究任务使用固定检查点图：

```text
界定问题 -> 建立检索图 -> 收集来源 -> 阅读原文
-> 比较证据 -> 综合 -> Evidence Guard -> 报告
```

任务支持暂停、恢复、取消和定向追加要求。取消是单调终态：界面立即显示停止，任何晚到的 Provider、网页或工具结果都不能再写入消息、来源、制品或业务数据。

完成结果区分实际引用、已查阅但未引用来源、证据缺口和下一动作。只有用户明确选择后，研究任务才会升级为 Campaign。

在 Composer 选择“研究任务”即可创建任务；目标、产物、来源范围和深度都有可直接运行的默认值。活动任务显示在非模态任务条或侧栏中，任务自己的输入框用于向该任务追加要求。暂停后可恢复，取消后不可恢复为运行状态，但已形成的审计记录仍可查看。普通 Composer 始终创建新的询问，不会暗中 steer 某个研究任务。

## EAI 的上下文优势

每轮 Agent 运行都会生成 `ContextManifest`，记录本轮实际可见内容的对象 ID、revision、来源层、信任等级和内容 hash。上下文优先级固定为：

```text
本轮显式附件 -> 当前焦点对象 -> 线程固定资料
-> 项目与对象记忆 -> Atlas -> 外部来源
```

冲突内容并存，不会被后到内容静默覆盖。最小线程上下文只帮助理解请求，不能自动变成证据。只有经过注册能力转换为证据记录的内容才能进入引用链。

这种设计让 Agent 不只是看到一段聊天记录，而是理解当前项目、线程、论文、Canvas、对象记忆、研究图谱和 Campaign 进度，同时仍能回答“本轮到底看到了什么”。

## 来源策略

| SourcePolicy | 最小线程上下文 | 本地/Atlas 证据 | 外部检索 |
|---|---:|---:|---:|
| `none` | 允许 | 禁止 | 禁止 |
| `atlas_only` | 允许 | 仅 Atlas | 禁止 |
| `local_only` | 允许 | 允许 | 禁止 |
| `external_only` | 允许 | 禁止 | 允许 |
| `local_and_external` | 允许 | 允许 | 允许 |

显式策略高于路由、模式和模型决策。未知策略返回 `422`，并且不会产生网络请求。模型端点只提供模型推理；EAI 不假设它自带网页搜索。设置页可直接选择 OpenAI、自定义兼容、OpenRouter、Anthropic、Gemini、DeepSeek、Qwen、xAI、Groq、SiliconFlow、Kimi、Ollama 或 LM Studio；Anthropic 使用原生 Messages，其余预设使用兼容的 Responses 或 Chat Completions。模型 ID 与请求地址仍可编辑。

SourcePolicy 位于 Composer 的独立来源控件中，默认值是 `local_and_external`（界面显示“全部可用来源”）。发送前摘要与运行审计都会显示实际策略、已使用来源和不可用连接器。

## 证据与引用

研究回答先形成结构化 `AnswerDraft`。Evidence Guard 检查来源是否属于当前任务、证据是否存在、locator 是否可解析、引用定位是否一致，以及证据等级是否足以支撑声明。

Guard 失败时，系统只显示证据缺口和补救动作，不交付未核验的事实正文。界面使用“引用定位已核验”“证据有限”“未通过核验”等表述，不把引用完整性误写成事实真伪证明。

PDF 引用采用版本化规范化流程处理 Unicode、断词、连字符、OCR 空格和标点差异，并保存规范化 hash、页码与字符映射。歧义匹配会降级，不使用宽松模糊命中冒充精确引用。

## Agent 能操控什么

能力注册表是系统唯一的权限真相。能力分为：

- **自动读取**：线程、项目、Atlas、文档、Canvas、对象记忆和 Campaign 摘要。
- **临时导航/预览**：通过受限 `UICommand` 打开界面对象，不直接操作 DOM。
- **可逆持久写入**：项目、线程、上下文、Canvas、候选和对象记忆等，通过 OperationBatch 确认。
- **外部执行**：实验和命令需要独立审批，只允许在受限 Docker 工作区运行。
- **禁止**：SQL、原始数据库、密钥、任意宿主路径、宿主命令和未注册能力。

OperationBatch 在执行前校验 revision 和真实 before 值。权威实体和 `projection_journal` 在同一个 SQLite transaction 中提交；JSON 投影在提交后独立重放。拒绝、冲突或预检失败均保持权威数据零写入。

用户可在 Run Center 的“Agent 能力”视图查看当前注册能力、权限类别、连接器健康和不可用原因。自然语言中的保存、创建、更新、删除和执行请求会先被确定性路由到操作/执行边界；否定式请求不会生成写入批次。

### Campaign 的 Docker 边界

Campaign 在创建实验会话和阶段跃迁时分别审批。审批界面显示镜像、命令、只读 seed、挂载、CPU/内存、超时和网络范围；一次批准只覆盖该次明确的分支会话或阶段动作。模型密钥不进入容器，Docker 不可用时不执行。分支输出和 checkpoint 进入 EAI 管理的 Campaign 运行目录，只有用户确认晋升的 finding、task 和引用才写回权威研究状态。

## 数据与隐私

- 个人数据默认位于 `%APPDATA%\com.eai.desktop`。
- Provider Key 保存在 Windows Credential Manager。
- sidecar 使用随机 loopback 地址和每次启动生成的会话令牌。
- Atlas、上游资源、旧数据库和用户来源快照不会被原地修改。
- 自动测试使用隔离目录，不读取真实 AppData。
- Research Store schema 较新时，旧应用应只读启动，不能尝试降级或重建。

远程模型会接收完成本轮所需的消息、允许上下文和筛选后的证据；搜索连接器会接收查询词；目标网页会收到正常 HTTPS 请求。EAI 负责最小化和约束发送内容，但第三方保留策略由对应 Provider 决定。`none`、`atlas_only` 和 `local_only` 只限制证据与搜索来源，不会阻止远程模型推理请求；敏感内容必须完全留在设备内时，应使用本机 loopback 模型 Provider。

备份时应先完全退出应用，再复制 `%APPDATA%\com.eai.desktop`。恢复应使用同一主版本的完整目录，不要让实验版 0.x 写入 v1.0 数据。数据库升级失败会恢复在线备份；JSON 投影失败则保留 journal 并重放，不回滚已提交的权威 SQLite 状态。

## 适合与不适合

EAI 适合论文调查、证据比较、研究路线整理、可复现实验规划和持续研究记录。它不适合作为任意操作系统自动化工具，也不应被当成事实真理机、通用数据库管理器或绕过审批的代码执行器。

v1.0 是 Windows x64 桌面版本，安装包尚未代码签名。完整 Campaign 执行需要 Docker；通用网页搜索需要独立连接器；当前不提供向实验版 0.x 的官方降级。
